# 계절노동 인권·안전 현장점검 앱 (시범운영판 v0.1)

외국인 계절노동자 인권·안전 실태 현장점검을 위한 오프라인 모바일 웹앱(PWA)입니다.
서버·데이터베이스·로그인이 없고, 점검 기록은 각 기기 안(IndexedDB)에만 저장됩니다.

- 기준 문서: 「'26년 하반기 외국인 계절노동자 인권실태 점검 계획(관계부처 합동)」 붙임3·4·5
- 점검 흐름: 점검 유형 선택 → 익명 대상 번호 선택 → 점검기준 확인 → 준수 여부 체크 → 미준수 사유 복수 선택 → 지적·권고 자동 생성 → 결과 검토 → A4 보고서 PDF 저장

---

## 1. 구성

```
field-inspection-pwa/
├─ index.html                 앱 진입 화면
├─ manifest.webmanifest       홈 화면 설치 정보(PWA)
├─ sw.js                      오프라인 캐시(앱 파일만 저장)
├─ css/app.css                화면 스타일
├─ css/print.css              A4 보고서·인쇄 스타일
├─ js/config/checklists.js    ★ 점검 문항·응답옵션·미준수 사유·지적/권고 문안·점검기준(수정 대상)
├─ js/engine.js               규칙 기반 판정·문안 생성
├─ js/storage.js              기기 저장소(IndexedDB, 대체: localStorage)
├─ js/report.js               A4 보고서 생성
├─ js/samples.js              시연용 익명 예시 데이터
├─ js/app.js                  화면·동작
├─ icons/                     앱 아이콘
└─ docs/SECURITY.md           보안 한계 및 기관 승인 절차
```

외부 라이브러리·글꼴·분석도구·CDN을 쓰지 않습니다. 모든 파일이 이 폴더 안에 있습니다.

## 2. 점검 모듈

| 모듈 | 근거 | 저장 내용 |
|---|---|---|
| 고용주(농가) 점검 | 붙임4, 17개 항목 | 항목별 결과, 미준수 사유 코드, 확인 방법, 배정·도입 인원, 국가 |
| 시·군 점검 | 붙임3, 7개 항목 + 운영현황 | 항목별 결과, 사유 코드, 건수·일자, 기관 건의사항 |
| 권익침해 식별지표 | 붙임5 | **저장하지 않음** — 문항 열람, 중대 침해 시 조치 절차 안내만 제공 |

- 응답옵션은 점검표 원문(준수/미준수, 여/부, 미해당)을 그대로 쓰고, 모든 항목에 '미확인'을 추가했습니다.
- 대상은 '방문 농가 1', '점검 시·군 1'처럼 익명 순번으로만 기록합니다. 같은 번호가 있으면 경고합니다.
- 사업장명·대표자·주소·연락처·노동자 정보는 입력 칸이 없습니다. 보고서에는 사업장명과 점검자 서명란이 빈칸으로 출력되어 현장에서 수기로 적습니다.

## 3. 미준수 사유·문안 규칙 수정

`js/config/checklists.js` 한 파일만 고치면 됩니다.

```js
{
  id: 'F-B4', short: '화재감지기·소화기',
  q: '화재감지기, 소화기 보유',                 // 점검표 원문(변경 금지)
  statusSet: 'comply',
  combine: { f: '숙소 내 {o} 등 화재예방 설비 미흡', r: '{a} 등 숙소 화재예방 조치 필요' },
  reasons: [
    { c: 'B4-DETECT', l: '화재감지기 미설치', o: '화재감지기', a: '화재감지기 설치' },
    { c: 'B4-EXT',    l: '소화기 미비치',     o: '소화기',     a: '소화기 비치' }
  ]
}
```

- `f` / `r`: 사유 하나를 선택했을 때 지적·권고 문안
- `combine`: 같은 항목에서 여러 사유를 고르면 `{o}`(대상어)·`{a}`(조치어)를 '및'으로 묶어 한 문장으로 만듭니다.
  예) 화재감지기 미설치 + 소화기 미비치 → "숙소 내 화재감지기 및 소화기 등 화재예방 설비 미흡"
- `verify: true`: 지적사항이 아니라 '추가 확인 필요 사항'으로 분류(증빙 미제시 등)
- 모든 항목에 '기타 확인 필요' 사유가 자동으로 붙고, 이것도 '추가 확인 필요 사항'으로 분류됩니다.

**주의**: 사유 분류·지적/권고 문안·확인 서류·현장 질문은 점검계획에 규정된 내용이 아니라 운영 참고용 제안입니다. 기관 검토 후 확정해 쓰십시오. 앱은 법령 위반이나 행정처분을 판정하지 않습니다.

파일을 고친 뒤에는 `sw.js`의 `CACHE` 값(예: `fi-v0.1.0` → `fi-v0.1.1`)을 올려야 설치된 기기에 반영됩니다.

## 4. 로컬에서 실행해 보기

서비스워커는 `http://localhost` 또는 `https`에서만 동작합니다.

```bash
cd field-inspection-pwa
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

`설정·데이터 관리 → 예시 불러오기`로 익명 예시 3건을 넣어 시연할 수 있습니다.

## 5. GitHub Pages 배포(시연용)

> 기관 정보보안 승인 전에는 공개 저장소에 올리지 마십시오(docs/SECURITY.md 참고).
> 이 폴더에는 점검 결과·내부 문서가 들어 있지 않지만, 점검계획 원문 PDF 등 내부 자료는 절대 함께 올리지 마십시오.

1. GitHub에서 새 저장소 생성(예: `field-inspection-pwa`). 가능하면 기관 조직 계정 아래 만듭니다.
   - 무료 계정은 공개 저장소에서만 Pages를 쓸 수 있습니다. 비공개 저장소의 Pages는 유료 플랜이 필요합니다.
   - 저장소가 비공개여도 **Pages 사이트 주소는 기본적으로 누구나 접속할 수 있습니다.** 접속자 제한은 GitHub Enterprise Cloud에서만 설정할 수 있습니다.
2. 이 폴더의 파일 전체를 저장소 최상위에 업로드합니다(`index.html`이 최상위에 있어야 함).
   ```bash
   git init && git add . && git commit -m "현장점검 앱 시범운영판 v0.1"
   git branch -M main
   git remote add origin https://github.com/<계정>/field-inspection-pwa.git
   git push -u origin main
   ```
3. 저장소 `Settings → Pages → Build and deployment`에서 Source를 `Deploy from a branch`, Branch를 `main` / `/(root)`로 저장합니다.
4. 1~2분 뒤 `https://<계정>.github.io/field-inspection-pwa/` 주소가 생성됩니다. 이 주소를 실원에게 공유합니다.

## 6. 기기에 설치(홈 화면 추가)

**iPad·iPhone (Safari)**
1. Safari로 배포 주소를 엽니다(다른 앱 안의 브라우저 말고 Safari 직접).
2. 주소창 옆 공유 버튼 → '홈 화면에 추가' → '추가'.
3. 홈 화면 아이콘으로 한 번 실행합니다. 이때 앱 파일이 기기에 저장되어 이후 인터넷 없이 실행됩니다.

**Android (Chrome)**
1. Chrome으로 주소를 엽니다.
2. 메뉴(⋮) → '홈 화면에 추가' 또는 '앱 설치'.

설치 후 화면 오른쪽 위 표시가 '오프라인 사용 중'이어도 점검 입력·저장·보고서 출력이 모두 됩니다.

## 7. PDF 저장

보고서 화면의 'PDF 저장 · 인쇄'를 누르면 기기 인쇄 기능이 열립니다.

- iPad·iPhone: 인쇄 옵션 화면 → 공유 버튼 → '파일에 저장'
- Android: 프린터 선택 → 'PDF로 저장'
- PC: 대상 → 'PDF로 저장'

기기 글꼴로 그리기 때문에 한글이 깨지지 않습니다. 완료 보고서 여러 건을 선택해 한 파일로 저장할 수 있습니다(보고서마다 새 쪽).
앱은 메일 발송이나 자동 전송 기능이 없습니다. 저장한 PDF를 기관 절차에 따라 직접 전달하십시오.

## 8. 저장소 한계(꼭 안내)

- 기록은 그 기기·그 브라우저에만 있습니다. 다른 기기에서 보이지 않고 백업되지 않습니다.
- 다음 경우 기록이 지워질 수 있습니다: 브라우저 데이터 삭제, 홈 화면 앱 삭제, 기기 초기화·분실, 저장공간 부족, (iOS) 장기간 미사용.
- 개인정보 보호(비공개) 모드에서는 저장되지 않습니다. 앱이 경고를 띄웁니다.
- 점검을 마칠 때마다 PDF로 저장하고, 제출이 끝나면 '설정 → 기록 모두 삭제'로 지웁니다.

## 9. 향후 확장 구조

- `js/storage.js`의 저장소 인터페이스(`list/get/put/remove/clear/getMeta/setMeta`)를 그대로 구현한 기관 서버용 어댑터를 만들면 화면 코드를 바꾸지 않고 중앙 DB로 전환할 수 있습니다.
- 점검 기록은 `{ module, seq, label, date, status, answers: { 항목ID: { status, reasons[], methods[], extra{} } }, edits{}, configVersion }` 구조이며, 사유는 코드로 저장되어 반복 지적 분석·시정 이력 관리에 바로 쓸 수 있습니다.
- 새 점검 모듈(농촌인력중개센터, 기숙사 등)은 `checklists.js`의 `modules`에 같은 형식으로 추가하고, `app.js` 새 점검 화면의 모듈 목록(`['farm','sigun']`)에 이름을 넣으면 됩니다.
