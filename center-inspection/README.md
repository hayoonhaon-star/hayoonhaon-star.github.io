# 농촌인력중개센터 운영실태 현장점검 앱 (시범운영판 v1.0)

농촌인력중개센터(농촌형)와 공공형 계절근로 운영기관의 운영실태를 현장에서 점검하는 오프라인 모바일 웹앱(PWA)입니다.
서버·데이터베이스·로그인·외부 API가 없고, 점검 기록은 각 기기 안(IndexedDB)에만 저장됩니다.

- 기준 문서: 「'26년 농촌인력중개센터 시행지침」(농림축산식품부, 2026. 9.), 「'26년 하반기 농촌인력중개센터 운영실태 점검 계획」('26. 10. 14.) 붙임 2·3
- 업무 흐름: 점검관리 → 사전점검 → 현장점검 → 미흡 사유·시정 권고 → 결과·보고서(PDF) → 시정조치(후속관리) → 대시보드
- 배포 주소(예정): `https://hayoonhaon-star.github.io/center-inspection/`

---

## 1. 폴더 구성

```
center-inspection/
├─ index.html                      앱 진입 화면
├─ manifest.webmanifest            홈 화면 설치 정보(PWA)
├─ sw.js                           오프라인 캐시(앱 파일만 저장)
├─ css/app.css · css/print.css     화면 · A4 인쇄 스타일
├─ js/config/criteria.js           ★ 점검 항목·근거·확인서류·미흡 사유·권고 문안·자동 검증 기준(수정 대상)
├─ js/engine.js                    규칙 기반 검증·권고 문안 생성
├─ js/storage.js                   기기 저장소(IndexedDB, 대체: localStorage)
├─ js/xlsx.js                      사전제출 엑셀 읽기(외부 라이브러리 없음)
├─ js/report.js                    결과 보고서 · 시정조치 요청서 · 현장점검표(붙임 2·3)
├─ js/samples.js                   시연용 예시(가상 관리번호)
├─ js/app.js                       화면·동작
├─ icons/                          앱 아이콘
└─ docs/
   ├─ 사용자매뉴얼.md               실원용 사용 설명서(백업 절차 포함)
   ├─ SECURITY.md                  보안 한계 및 기관 승인 절차
   ├─ 점검항목_사유_권고_대응표.md   항목별 근거·사유·권고 대응표(설정 파일에서 자동 생성)
   ├─ 사전제출양식.xlsx             지방정부 배포용 사전제출 양식
   └─ 예시_백업.json                예시 데이터(가상 관리번호) — 백업 복원 시험용
```

외부 CDN·글꼴·분석도구를 쓰지 않습니다. 콘텐츠 보안 정책(CSP)으로 같은 주소 외 연결을 막습니다(`connect-src 'self'`).

## 2. 점검 구성

| 구분 | 분야 | 항목 수 |
|---|---|---|
| A. 농촌형 농촌인력중개센터 | 운영 일반 및 관리체계, 인력풀 등록·관리, 구인·구직 모집 및 중개, 고용·근로자 지원, 예산 집행 및 회계, 성과관리 및 운영개선 | 29 |
| B. 공공형 계절근로 운영기관 | 운영 일반 및 관리체계, 계절노동자 배정·노동력 제공, 고용·근로자 지원, 예산 집행 및 회계, 성과관리 및 운영개선, 공동 숙식시설 관리 | 23 |

- 항목별 결과: **적정 / 미흡 / 해당없음 / 확인필요**
- '미흡' 선택 시 항목별 미흡 사유(복수 선택, '기타'는 내용 필수), 현장 확인 내용(필수), 시정 권고(사유에서 자동 작성·수정 가능)가 펼쳐지며, 셋 중 하나라도 비면 점검을 완료할 수 없습니다.
- 시행지침에 판단 기준이 구체적으로 없는 항목은 **[행정 확인 필요]**로 표시됩니다(A 8개, B 5개).
- 자동 검증은 시행지침에 명시된 수치(교통비·숙박비·간식비·작업반장 수당 상한, 최저임금, 편성비율 등)만 씁니다. '기준 위반(수치 확인)'과 '사람 확인 필요'를 구분하며, 센터를 자동으로 부적정 판정하지 않습니다.

## 3. GitHub Pages 배포

### 3-1. 처음 배포
1. 이 `center-inspection` 폴더를 GitHub 저장소(예: `hayoonhaon-star.github.io`) 최상위에 올립니다.
   - 웹에서: 저장소 → **Add file → Upload files** → 폴더째 끌어다 놓기 → **Commit changes**
2. 저장소 **Settings → Pages**에서 배포 브랜치(main)가 켜져 있는지 확인합니다.
3. 1~2분 뒤 `https://<계정>.github.io/center-inspection/` 으로 접속합니다.

모든 경로가 상대 경로라 `/center-inspection/` 하위 폴더에서 그대로 동작합니다. 다른 폴더 이름으로 올려도 됩니다.

### 3-2. 수정 배포
1. 파일을 고친 뒤 **sw.js의 `CACHE` 값을 올립니다**(예: `ci-v1.0.0` → `ci-v1.0.1`). 올리지 않으면 이미 설치한 기기에 새 버전이 반영되지 않습니다.
2. 저장소에 덮어써 올립니다. 사용자가 앱을 다시 열면 자동 갱신됩니다.

### 3-3. 점검 기준 수정
`js/config/criteria.js`만 고치면 항목·근거·사유·권고·수치 기준이 바뀝니다. 수정 후 `version` 값과 sw.js의 `CACHE` 값을 함께 올리십시오.
대응표 문서는 아래 명령으로 다시 만들 수 있습니다(Node.js 필요, 선택 사항).

```
node tools/gen-map.cjs
```

### 3-4. 로컬 시연
```
cd center-inspection
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080/
```
`file://`로 직접 열면 서비스워커(오프라인 설치)가 동작하지 않습니다.

## 5. 저장·백업

- 기록은 입력할 때마다 기기 안에 자동 저장되며, 새로고침해도 유지됩니다.
- 브라우저 데이터 삭제, 앱 삭제, 기기 초기화 시 기록이 사라집니다. **[설정·백업 → 전체 백업]**으로 JSON 파일을 내보내 원 내부 공유폴더에 보관하십시오.
- 복원 시 형식을 검사하고, 같은 점검번호는 더 최근 수정본만 반영하며, 기존 기록을 자동으로 지우지 않습니다.
- 내보내기 전 자유 기재란에서 전화번호·등록번호·이메일 등 개인정보로 보이는 형식을 찾아 알려줍니다(기본 패턴 검사로 완전한 보호를 보장하지 않음).

## 6. 확인된 한계

| 구분 | 내용 |
|---|---|
| PDF | 별도 PDF 라이브러리 없이 브라우저 인쇄 기능의 'PDF로 저장'을 씁니다. iPhone·iPad는 인쇄 화면에서 공유 → PDF 저장 |
| 엑셀 불러오기 | 브라우저 내장 압축 해제 기능을 씁니다. iOS 16.4 미만 등 오래된 브라우저는 지원하지 않으며, 이때는 사전점검 화면에 직접 입력 |
| 접근 통제 | 공개 주소이므로 앱 화면은 누구나 열 수 있습니다. 화면 비밀번호는 실제 보안 통제가 아니므로 두지 않았습니다 |
| 데이터 공유 | 서버가 없어 실원 간 자동 공유는 없습니다. 백업 파일을 주고받아 대시보드에서 합칩니다 |
| 기준 검증 | 항목·사유·권고는 시행지침 기준 초안입니다. 시범운영 전 소관 부서 검토가 필요합니다 |

## 7. 2027년 확장 대비

- 기록 구조에 `schema`, `configVersion`, 관리번호(`centerId`, `inspectorId`, `INS-연도-순번`, `CASE-…`)를 두어 중앙 시스템 이관 시 그대로 적재할 수 있습니다.
- `storage.js`는 `list/get/put/remove/clear/getMeta/setMeta` 인터페이스로 분리되어 있어, 기관 서버 연동 시 같은 인터페이스의 원격 저장소로 바꾸면 화면 코드를 고치지 않아도 됩니다.
